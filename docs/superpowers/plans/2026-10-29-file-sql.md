# Native FileSQL implementation plan

Goal: implement local read-only file relations in the seekdb SQL engine. The
first vertical slice is streaming CSV with normal SQL projection, filters,
aggregation, ordering and joins. JSONL follows on the same scanner interface.
Parquet, glob, DESCRIBE and COPY remain separate follow-up slices; no partial
slice will be labelled the complete 50-point task.

## Architecture and accepted constraints

- A dedicated FROM call parse node binds a literal path and named options.
- Reuse FUNCTION_TABLE logical planning. Add an explicit file-table flag to
  TableItem and deep copy it. Store bounded, serialized immutable file binding
  metadata in its allocator-owned constant function_table_expr_. This avoids
  retaining resolver-memory or operating-system descriptors in a cached plan.
- Bind all columns after a full, bounded-memory schema pass; use source ordinals
  for column IDs. The schema pass must not retain file rows.
- A dedicated vectorized PHY_FILE_SCAN supplies rows to ordinary native query
  operators. Leave existing PL/function-table runtime behavior unchanged.
- FileScanSpec stores the binding expression, referenced output expressions and
  their source ordinals. COUNT(*) must work with zero referenced output columns.
- The scanner owns an FD, bounded record buffers and schema state. It verifies
  regular-file identity/size/timestamps on open, rescan, during reads and at EOF.
- FileSQL defaults OFF through enable_file_sql (session/global bool). Read current
  secure_file_priv again during execution; fail closed for empty/NULL policy,
  NUL paths, nonregular files, traversal and symlink/race escapes. Do not use the
  existing check_secure_path whitelist fallback.
- No external query engine, no full-file JSON/PL collection, no fake successful
  results, no filename/content-specific behavior.

## Scanner interface shared by the independent work streams

Namespace oceanbase::sql::file_sql. Header ob_file_scan_utils.h uses standard
bounded string/vector types and the existing RapidJSON headers for JSONL and
binding serialization. Types: Format {CSV, JSONL}; Type {NULL_VALUE, BIGINT,
DOUBLE, BOOLEAN, VARCHAR, DATE, DATETIME}; Options (header=true, delimiter=',',
quote='"', escape='"', nullstr="", sample_size=-1); Column {name,type,max_length};
Cell {text,is_null}; Binding (format,options,path,columns,file fingerprint).

Functions return Status {OK=0, END=1, INVALID=-1, DENIED=-2, CHANGED=-3,
IO_ERROR=-4, UNSUPPORTED=-5, LIMIT_EXCEEDED=-6}, with a diagnostic string:

```
int infer_file(const std::string &path, const std::string &secure_dir,
               Format format, const Options &, Binding &, std::string &error);
int serialize_binding(const Binding &, std::string &json, std::string &error);
int deserialize_binding(const std::string &json, Binding &, std::string &error);
class Scanner {
  int open(const Binding &, const std::string &secure_dir, std::string &error);
  int next(std::vector<Cell> &row, std::string &error);
  int rescan(std::string &error);
  void close();
};
```

Header uses #pragma once; newly introduced types have no Ob prefix. Utility
implementation owns its security/parsing/inference tests. Kernel integration
owns parse/bind/config/operator/SQL tests. Agree on API before integration.

## TDD and verification gates

1. Add failing scanner tests: quoting/CRLF/multiline/NULL/UTF-8/headers/type
   widening, malformed rows, oversized records, path escaping, changed file,
   partial reads and rescan. Test real production utility implementation.
2. Implement bounded reader and deterministic inference; preserve RED logs and
   run all tests under sanitizers. Compile with actual native build flags.
3. Add real SQL cases initially failing on 140f: disabled/default behavior,
   aliases/named options, typed projection, reordered projection, COUNT(*),
   filter/ORDER/LIMIT/GROUP/HAVING and CSV INNER/LEFT JOIN/rescan.
4. Implement kernel linkage and generated sysvar metadata; compile actual
   production units before scheduling one full native build.
5. Run new binary SQL cases and unchanged official fixtures where supported;
   record unsupported Parquet/DESCRIBE/COPY explicitly until implemented.
6. Add JSONL scalar-only parsing, first-seen union/missing NULL and cross-format
   joins, with new failure cases before implementation.
7. Independent review, regression tests and full build precede pushing any
   implementation as ready. Never modify supplied official test/benchmark assets.
